# 第八輪預先登錄：分開「讀出」與「先知道」——前處理 L2 / L3

本文件在建立任何 L2、L3 資料包、跑任何辨識測試或風險評分**之前**提交。之後若有修改，寫在第 9 節修訂紀錄，並說明原因。

## 1. 問題
第七輪基準方法 B 把未遮蔽的 10-K 交給 LLM，AUC 0.90，但 28 家全部被認出，模型「不知道後來出事」的 15 份 AUC 只有 0.04。無法分辨模型是「讀出」年報裡的訊號，還是因為「先知道結果」才挑出這些訊號。

本輪的做法：同一批年報做成數個遮蔽等級，逐級切斷「身分」這條路徑，同時保留「內容」。每一級都測量辨識率與 AUC。本文件先登錄 **L2、L3 的前處理規則**與**遮蔽有效性檢查**；評分提示詞、交換身分測試、L4（只有數字）與評分模型，在開始評分前另行補登錄（第 7 節）。

## 2. 樣本
- 第七輪的 28 份 Y0 10-K（14 家 AAER 問題公司、14 家程式選出的同產業對照），申報編號與 `data/round7/packets/manifest.json` 相同
- Y0 = Y0 期末日的年份（例如期末 2017-06-30 → Y0 = 2017）

## 3. 資料包重建（L0′）
- 第七輪的資料包有擷取錯誤：`round6_llm._clean` 把只有 1–3 位數字的行當成頁碼刪除，而 HTML 解析器在 inline XBRL 標籤處把內文斷行，所以內文中「$245 million」這類數字的 245 被刪掉。28 份中有 20 份受影響（`$` 後面直接斷行的次數最多 316 次）
- 本輪用新的解析器重新下載、擷取同一份申報（10-K 主文件加 EX-13）：
  - 內文以段落為單位，inline 標籤不斷行
  - 表格每一列輸出成 `| 儲存格 | 儲存格 |`
  - 不刪除任何數字行
- **L0′ = 修正後的原文**，不遮蔽。第七輪的 L0 結果因此不能直接和本輪比較，L0′ 需要重新評分
- 舊程式不修改，前幾輪結果仍可重現

## 4. L2：全文保留，逐字遮蔽
步驟依序執行（順序有影響）。

### 4.1 識別清單（程式自動建立，不靠人工判斷）
- SEC `submissions` API：公司名稱、曾用名、股票代號、EIN、營業與郵寄地址（街道、城市、郵遞區號）、電話
- 申報檔的 Exhibit 21：所有子公司名稱
- 10-K 本文：所有 `/s/ 姓名` 簽名（董事、主管、會計師事務所）
- 會計師事務所：常見事務所名稱清單（四大與中型所）
- 公司名稱的變體：去掉 Inc、Corp 等字尾的名稱；名稱第一個字（長度 ≥ 4 且在該份年報中從未以小寫出現）

### 4.2 替換成有型別、有編號的代號
- 公司本身 → `[COMPANY]`；股票代號 → `[TICKER]`
- 子公司 → `[SUB_n]`；人名 → `[PERSON_n]`；會計師事務所 → `[AUDITOR]`
- 同一份資料包內，同一個名稱永遠用同一個編號；編號只在該份資料包內有效

### 4.3 格式比對
- CIK、SEC 檔案編號（`001-12345`、`333-123456`）、EIN、CUSIP、電話、郵遞區號、網址、email → `[ID]`、`[URL]`
- 訴訟案號（`Case No.`、`Civil Action No.` 後的編號）→ `[CASE_NO]`

### 4.4 其餘專有名詞
- 沿用 `redact.py` 的規則：大寫開頭的詞，若在同一份年報中從未以小寫出現，就是專有名詞
- 改進一：連在一起的專有名詞視為同一個實體，編號 `[NAME_n]`，同一份資料包內一致
- 改進二：國名換成 `[COUNTRY_n]`；洲名與區域（Europe、Asia、Latin America、North America、EMEA、APAC）保留

### 4.5 年份
- 四位數年份 → 相對年度（Y0、Y-1、Y+1），沿用 `redact.py`
- 新增：`FY22`、`FY2022`、`fiscal 2022`、`’21` 也轉換
- ASU 編號（`ASU 2016-02`、`ASU No. 2016-02`）→ `ASU [no.]`，保留 ASC 主題編號
- 月、日保留
- 年代線索（COVID-19、Tax Cuts and Jobs Act 等）保留：單獨的年代無法認出公司，且常本身就是訊號

### 4.6 數字（在年份轉換之後）
- 每家公司抽一個不公開的係數 k：log k ~ Uniform(log 0.5, log 2)，以固定種子抽出，存於 `data/round8/key.json`
- **乘上 k 的**：所有金額，包括
  - 內文中 `$` 開頭的金額（含 million、billion、thousand 等單位，單位不變）
  - 金額表格中的數字儲存格。金額表格的判定：該表任一列含 `$`，或表格上方 3 行內 / 表格內含「in thousands / millions / billions」
  - 每股金額（EPS、每股股利、股價）
- **不乘的**：百分比、比率、股數（列名含 shares 但不含 per share）、Note 與 Item 編號、已轉成 Y 的年份、列名含 employees、number of、days、years、months、rate、ratio、% 的列，`7 to 15` 這類期間範圍
- 縮放後保留原本的小數位數。因為四捨五入，加總可能差 ±1
- 非金額的計數：員工、店數、據點、坪數、面積等（數字後面接 employees、stores、locations、facilities、square feet、acres 等，且 ≥ 100）→ 取兩位有效數字
- 線性縮放使所有比率、成長率、加總關係不變

## 5. L3：L2 再加上整段刪除
### 5.1 保留的段落
Item 1A 風險因素、Item 1B 未解決的 SEC 意見、Item 3 法律訴訟、Item 7 MD&A、Item 7A 市場風險、Item 8 財務報表與附註、Item 9、9A、9B，以及 EX-13（年報中的 MD&A 與財務報表）。

### 5.2 刪除的段落
封面與目錄、Item 1 業務、Item 1C 資安、Item 2 不動產、Item 4、Item 5 股價與股東、Item 6、Item 10–14、Item 15–16（附件與報表索引）、簽名頁。若 Item 8 只寫「參見 Item 15」，則保留 Item 15 中的財務報表部分。

### 5.3 固定格式摘要（取代 Item 1，每家格式一樣）
```
產業：SIC 前 2 碼的大類名稱 | 規模等級：總資產 <1 億 / 1–10 億 / 10–100 億 / >100 億美元 | 會計年度結束：第 n 季
```
規模等級依第七輪 `controls.json` 的 XBRL 總資產（未縮放）。

### 5.4 刪除描述性句子
在保留的段落中，符合下列任一條的句子整句刪除：
- 自我描述：`we are a / an / the`、`the Company is a / an / the`、`[COMPANY] is a`、headquartered、principal executive offices
- 市場地位：`the / a leading`、largest、premier、foremost、`the only`、`the sole`、`market / industry / world leader`、market share、pioneer、`#1`、`No. 1`
- 沿革：`founded in`、`incorporated in`、initial public offering、went public、special purpose acquisition、SPAC

收購、處分、重組的句子**不刪**，只遮蔽名稱（它們本身是常見的舞弊訊號）。不用 LLM 改寫，避免改寫用的模型把事後知識寫進去。

## 6. 開始評分前的檢查
### 6.1 遮蔽有效性
1. **殘留掃描（程式）**：L2、L3 每份資料包中，識別清單上的項目（不分大小寫；股票代號分大小寫）出現次數必須為 0。CIK、檔案編號也必須為 0
2. **人工檢查**：列出每份資料包中出現最多的 50 個未遮蔽大寫詞，檢查是否有漏掉的專有名詞。檢查者只看詞表，不看標籤
3. **試跑辨識測試**：最多用 6 份 L3 資料包（3 份問題、3 份對照，隨機抽），每份開一個新的 agent，只問 `IDENTIFY_TASK`（第六輪的版本）。可依結果補強遮蔽規則
4. **規則凍結**：第一次風險評分開始後，遮蔽規則不得再修改。所有修改記在第 9 節

### 6.2 訊號保留
1. **金額縮放檢查（程式）**：L2 資料包中「Total assets」的 Y0 值 ÷ k，與第七輪 XBRL 總資產的相對誤差 < 1%（擷取得到的才比較）
2. **關鍵字分數**：第一輪的規則式分數 T（`score.score_filing`），對 L0′、L2、L3 各算一次。L2、L3 相對 L0′ 的下降幅度如實報告。下降很多的類別，代表遮蔽刪掉了訊號，判讀第 8 節時要考慮

## 7. 開始評分前另行補登錄的項目
- 評分模型（Claude agent 或 gpt-5.5）與次數
- 風險評分提示詞：沿用第七輪 `RISK_TASK`，加註「名稱已遮蔽、金額已乘上未公開的常數、比率不變、±1 為四捨五入」；辨識問題拆到獨立對話
- L4（只有 XBRL 數字）
- 交換身分測試（以 L2 為基礎，2 種內容 × 3 種名稱）
- 理由中的事後資訊檢查

## 8. 判讀（描述性；14 對 14 樣本太小，不做假設檢定）
| 觀察 | 解讀 |
|---|---|
| L0′ → L2 → L3，辨識率下降，AUC 也跟著降到 0.5 左右，且 6.2 顯示訊號大致保留 | 分數主要來自「先知道結果」 |
| 辨識率下降，AUC 維持；沒被認出的子樣本 AUC 也高 | 模型「讀出」訊號 |
| AUC 下降，但 6.2 顯示訊號也大量流失 | 無法區分，需要改進遮蔽方式 |

## 9. 修訂紀錄
- 2026-11-02，**L2 試跑（使用者要求，在任何風險評分之前登錄）**：
  - 範圍：第 1–5 組（P01T–P05C，10 份）
  - **輸入改用第七輪原本的資料包**（基準方法 B 讀的同一份文字），不用 L0′。理由：(1) 從 SEC 下載完整申報檔需要聯絡 email 的 User-Agent，本 session 未設定；(2) 和 B 用同一份輸入，L2 與 B 的差異就只來自遮蔽。代價：內文小數字遺失的問題保留（兩邊相同），且沒有 Exhibit 21，子公司由一般專有名詞規則遮蔽
  - 識別清單：SEC submissions API（名稱、曾用名、代號、地址、EIN、電話）＋ 10-K 中的 `/s/` 簽名 ＋ 會計師事務所清單
  - **評分方式依使用者要求**：每份開一個新的 Claude agent，**同一個對話**回答風險分數、是否認得公司、是否知道後來出事（與第七輪 B 相同，以便逐組比較）；提示詞為第七輪 `RISK_TASK` 加一段遮蔽說明（`round8.RISK_TASK_L2`）。第 7 節「辨識問題拆到獨立對話」留待正式評分
  - agent 只能讀取一個中性檔名的檔案（`report_NN.txt`，隨機順序，放在 repo 之外），對應表在 `agent_filename_map.json`
  - 規則修正（建包後、評分前，依殘留檢查）：(1) 檔名 `adm-20221231.htm` 洩漏代號 → 檔名格式改為 `[ID]`，3 字母以上代號不分大小寫；(2) `10-K` 的 K、全大寫標題中的 AND / TO / OR 被誤遮 → 保留；(3) `FY23` 先於專有名詞轉換

- 2026-11-02，**L2 試跑後、L3 評分前的修訂（第 2 版規則）**。依 `pilot_L2_results.md` 的發現：
  - **縮放規則改為「所有數量都乘 k」**：金額、股數、其他計數（員工數等）都乘 k；只有每股金額（數值必須帶小數，例如 2.92）、百分比、比率、利率、期間不乘。理由：第 1 版排除規則（列名含 year / per share / par value / price / %）把同一個數字在不同表格處理得不一致，製造了假的不一致。取消 4.6 節「計數取兩位有效數字」
  - 新增檢查：**同一個原始數字（≥ 4 位）若有時縮放、有時沒有，就列出**；10 份全部為 0
  - 單獨一行的數字（inline XBRL 斷行使 `$` 在上一行）也縮放
  - 遮蔽補強：所有檔名（`*.htm` 等）→ `[FILE]`；3 字母以上代號在接數字時也遮蔽（`1ADM`、`bdx2019`）；公司名稱縮寫（`BD`、`ADM`，在年報中出現 ≥ 3 次才算）→ `[COMPANY]`；年份規則擴大到 1800–2039；7 碼電話；州名後的郵遞區號；「名稱 + Inc / LLC / Corp」視為實體名稱（替代無法取得的 Exhibit 21）
  - **L3 新增**：部門名稱 → `[SEGMENT_n]`（取「… segment(s)」前出現 ≥ 2 次的大寫片語），並遮蔽其中具辨識性的單字（`Oilseeds`、`Rhythm`）；段落邊界在原文上判定，再以標記帶到遮蔽後的文字；Item 8 只有交互參照時，保留 Item 15/16 中從查核報告或資產負債表開始的財務報表
  - L3 試跑漏洞回歸：剩 `Compounding`（P04T，FDA 用語 Pharmaceutical Compounding）與 `Interventional`（P05C，醫材通用類別 Interventional Cardiology），判定為一般產業用語，不再遮蔽
