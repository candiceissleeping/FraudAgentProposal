# 第八輪：去除記憶污染的 LLM 舞弊風險評分（預先登錄）

本文件在建立任何事實卡、執行任何 agent 之前提交。

## 0. 為什麼要做這一輪
- 第七輪方法 B（整份 10-K 不遮蔽，直接問 LLM）AUC 0.90，但 28 家全被認出，問題公司 13/14 模型「知道後來出事」；只看模型不知道結果的 15 份，AUC 0.04。分數主要來自記憶。
- 第四輪就算用程式遮蔽名稱、人名、地名、年份、網址，72 份中仍有 62 份被認出。**只遮蔽文字不夠**：產品、業務描述、數字規模本身就能認出公司。
- 本輪目標：
  1. **切斷辨識**：讓評分的 LLM 認不出公司，也就無從「想起」它後來有沒有 AAER。
  2. **證明分數來自推理**：確認分數隨年報內容改變，不隨公司身分改變。

## 1. 樣本
沿用第七輪的 28 份 Y0 10-K（14 家 2023 年後 AAER 問題公司 + 14 家程式選出的同產業、同規模對照公司，`config/round7_cases.json`、`results/round7/controls.json`）。

選這個樣本是刻意的：在不遮蔽的情況下，模型 28/28 認得、13/14 知道結果。這是**最難的情況**，如果在這裡能切斷記憶，在模型不熟的公司上也會成立。

## 2. 方法：資訊瓶頸（先抽事實，再判斷，兩者分開）

```
10-K 原文 ──程式遮蔽──▶ 遮蔽文字 ──抽取 agent（固定欄位、逐字引文）──▶ 程式驗證引文
                                                                            │
XBRL 當時申報數字 ──程式──▶ 比率（四捨五入到 2 位小數）─────────────────────┤
                                                                            ▼
                                      事實卡（沒有名稱、年份、金額、產品、引文）
                                                                            │
                                                     判斷 agent（新開，只看事實卡）──▶ 風險分數 0–100
```

### 2.1 遮蔽文字（程式）
- 用第三、四輪的 `redact.make_redactor`：公司名稱、專有名詞 → `[NAME]`；網址、電子郵件 → `[URL]`；年份 → 相對年份（Y0、Y-1）
- 檔名改為隨機代碼（`R8-xx`），不帶 T/C、配對編號

### 2.2 抽取 agent（每份 10-K 一個新 agent）
- 只回答固定的 28 個欄位（`experiment/edgar_risk/round8.py` 的 `FIELDS`），每個欄位只能填封閉選項或數字
- 每個非「未找到」的答案都要附上遮蔽文字中的**逐字引文**
- 指示：只依文件內容回答，不可使用對公司的任何記憶；認得公司也不要說出名稱
- 抽取 agent 認不認得公司**不重要**：它的輸出只會通過程式驗證後的欄位值進入事實卡

### 2.3 程式驗證
- 引文在遮蔽文字中找不到（空白正規化後比對）→ 該欄位改為「未找到」。從記憶補出、原文沒有的事實會在這裡被剔除
- 記錄每份的引文驗證失敗率

### 2.4 事實卡（判斷 agent 唯一看得到的東西）
- 28 個欄位的值（不含引文，引文可能帶有可辨識的細節）
- XBRL 比率：Beneish 八項指標與 M 值、Dechow F 值及其組成、應計比率、應收成長減營收成長、CFO/淨利。四捨五入到 2 位小數。**不提供任何絕對金額、資產規模**
- 產業只給 SIC 大類（例如「製造業」「通訊」「金融」），不給 4 位數代碼
- 不提供公司名稱、會計年度、交易所、地點、審計師名稱

### 2.5 判斷 agent（主要分數 J0）
- 每張事實卡一個新 agent，只看這一張卡
- 回答：風險分數 0–100、理由（每條理由必須引用欄位代碼）、是否認為自己認得這家公司、名稱猜測、是否知道後來有會計問題或 SEC 執法

## 3. 目標一的檢驗：辨識是否被切斷

| 代號 | 檢驗 | 做法 | 通過標準 |
|---|---|---|---|
| G1a | 開放式辨識 | 2 個新 agent 各拿 14 張卡（隨機混合），盡力猜每張卡的公司名稱（最多 3 個）與會計年度 | 猜中（任一名稱正確）≤ 2/28 |
| G1b | 封閉式辨識（最強攻擊） | 1 個新 agent 拿全部 28 張卡**加上 28 家公司的名單**，替每張卡指定一家公司 | 正確數不顯著高於「只靠產業大類隨機猜」的期望值（單尾 p ≥ 0.05） |
| G1c | 判斷 agent 自述 | J0 的「知道後來有問題」 | ≤ 1/28 |

對照基準：第七輪不遮蔽 28/28 認出；第四輪遮蔽文字 62/72 認出。

## 4. 目標二的檢驗：分數是否來自推理而非記憶

| 代號 | 檢驗 | 做法 | 預期 / 通過標準 |
|---|---|---|---|
| MEM | 純記憶基準 | 1 個新 agent 只拿到 28 個「公司名稱 + 會計年度」，沒有任何年報內容，給風險分數 | 描述性。預期 AUC 很高，這就是記憶能貢獻的上限 |
| J1 | 事實卡 + 真實名稱 | 同 J0 的卡，但標上真實公司名稱 | 描述性。J1 − J0 在問題公司比對照公司大 → 名稱是記憶的開關 |
| J2 | 事實卡 + 對調名稱 | 問題公司的卡標上配對對照公司的名稱，反之亦然 | 描述性。看分數跟著「卡的內容」還是「標的名稱」走 |
| G2a | 理由可追溯 | 程式檢查 J0 每條理由引用的欄位代碼是否存在於卡上 | ≥ 95% 的理由引用有效欄位 |
| G2b | 內容擾動 | 7 張問題公司卡：把紅旗欄位改成無問題；7 張對照公司卡：加入 3 個標準紅旗（收入相關重大缺失、SEC 調查、年度內更換 CFO）。各開新 agent 評分 | ≥ 12/14 往預期方向移動，且 \|Δ\| 中位數 ≥ 10 分 |
| G2c | 與記憶分數無關 | 在問題組、對照組內分別去掉平均後，J0 與 MEM 的 Spearman 相關 | 描述性，\|ρ\| 越接近 0 越好 |

擾動挑選：問題組、對照組各依隨機代碼排序取前 7 張，由程式決定，不看分數。

## 5. 主要成效（描述性）
- J0 的 AUC（bootstrap 95% CI）、組內勝負；與第七輪 F（0.67）、B 不遮蔽（0.90）、B 不知道結果的子集（0.04）並列
- 樣本只有 14 對，AUC 只做描述，不宣稱方法有效

## 6. 判讀規則（事先寫定）
- G1a、G1b、G1c 都通過，且 G2a、G2b 通過 → 這個流程視為「去除記憶污染」，J0 的 AUC 是乾淨的估計（不論高低）
- G1 任一項未通過 → 事實卡仍洩漏身分；報告哪些欄位造成辨識，下一輪把它們粗化。J0 的 AUC 不能當作乾淨的估計
- G2b 未通過 → 分數對內容不敏感，判斷 agent 可能用了其他線索；J0 不能當作推理能力的估計

## 7. 已知限制
- 我（設計者）知道哪些是問題公司。欄位清單在看任何事實卡之前固定（取自 `results/methods_overview.md` 方法 5 的清單）；配對、擾動挑選、卡片內容都由程式產生
- 抽取 agent 仍可能「選擇性地」找證據（知道是問題公司就更努力找紅旗）。固定欄位、每欄都要回答可以降低但無法排除；下一輪可用兩個不同模型抽取比對
- 評分者都是同一個 Claude 模型（新開的 agent，看不到這段對話與標籤），結論只適用於這個模型
- 事實卡丟掉了年報中的許多細節，AUC 可能低於不遮蔽版本；這是為了乾淨所付的代價，本輪就是要量出這個代價

## 8. 修訂紀錄
- 2026-11-02：初版，在建立任何事實卡、執行任何 agent 之前提交
- 2026-11-02（執行任何 agent 之前）：檢查遮蔽結果時發現大小寫不同的公司名（例如 AerSale）與檔名沒被遮住。改為對公司名稱做不分大小寫的遮蔽（一般英文單字如 national、consolidated 除外），並遮蔽檔名、雇主識別碼、電話、委員會檔案編號
- 2026-11-02（抽取進行中、建立事實卡與執行任何判斷 agent 之前）：驗證程式原本把「沒有引文的否定答案」（no、none、na、none_or_na）也算成引文失敗，與抽取指示第 4 條（未提及時填 no、引文留空）不一致。改為：否定答案可無引文；任何肯定答案、數字答案仍必須有可在原文找到的引文

## 9. 追加實驗 8b：粗化事實卡（G1b 未通過後追加，在執行任何 8b agent 之前登錄）
- 原因：封閉式辨識（給 28 家名單）26/28 猜中。依據探針說明，可辨識的線索是：產業大類、精確到 2 位小數的比率（例如 SGI 1.16）、少見事實（SPAC／反向合併、單一客戶 96%）
- 粗化事實卡 C0（`round8.py cards_c`）：
  - 刪除產業大類與 F23（上市途徑）
  - 客戶集中度改為區間（<10%、10–25%、25–50%、>50%）
  - 比率全部改為固定切點的類別（切點寫在 `BINS`，取自 Beneish 原文的常用門檻）；M、F 只給「高於／低於門檻」；不提供任何數值
- 執行：1 個封閉式辨識探針（同一份 28 家名單）＋ 28 個 J0-C 判斷 agent（同一份 judge 提示詞）
- 通過標準：封閉式辨識正確 ≤ 3/28（28 選 1 隨機猜的期望 1，P(X ≥ 4) ≈ 0.02）
- J0-C 的 AUC 只做描述，與 J0 比較，量出粗化的代價
