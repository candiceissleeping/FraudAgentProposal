# 第八輪 MEM 驗證實驗：完整報告（實驗 A–D，2026-11-06 至 11-09）

本報告整理四個實驗：A 隔離環境重跑、B 時間外樣本、C 不同模型＋分層、D 查核「知道」自述。
依序說明實驗目的、實驗設計、實驗環境、實驗結果。

---

## 一、實驗目的

### 背景
第八輪的 MEM 條件只給 LLM「公司名稱＋會計年度」，不給年報，要它評估該年度財報被重大誤述的風險（0–100）。結果 AUC 0.88，幾乎等於第七輪「整份 10-K 直接評分」的 0.90。
這個數字只有在確定「LLM 沒有上網、只靠自己的記憶」時才可信；而就算是記憶，也還要分清楚是哪一種記憶。

### 總目的
1. 證明 MEM 的 0.88 不是上網或讀到答案得來的
2. 拆開「記憶」的兩種來源：
   - **記得結果**：模型記得這家公司後來重編或被 SEC 處分
   - **公司類型先驗**：模型不知道結果，只從名稱知道「這是哪類公司」（小型、OTC、SPAC 出身 vs. 大型老牌）
3. 判斷第七輪「整份 10-K 0.90」能不能解讀為 LLM 讀年報辨識舞弊的能力

### 各實驗要回答的問題
| 實驗 | 問題 |
|---|---|
| A 隔離重跑 | 在確定無法上網的環境中，MEM 還是 0.88 嗎？ |
| B 時間外樣本 | 模型不可能知道結果時，只看名稱的 AUC 是多少（公司類型先驗多大）？ |
| C 不同模型＋分層 | 第八輪的 0.88 是跟著「記得」走，還是跟著先驗走？記憶量不同的模型表現是否不同？ |
| D 查核「知道」 | 模型說「知道出事」時，是真的記得，還是看名字亂猜？ |

## 二、實驗設計

### 共同原則（四個實驗都適用）
- **預先登錄**：設計、指標、判讀標準先寫成 `protocol.md` 並 commit，之後才執行
- **先存原始紀錄、後讀標籤**：所有原始紀錄、回答、輸入名單 commit 之後才讀標籤；評估程式會檢查檔案已 commit 且未修改，否則拒絕計算
- **同一個無工具環境**：所有 LLM session（評分者也是）都在第三節的環境中執行，每次都要通過 7 項無上網檢查
- **輸入去除格式線索**：名稱統一大小寫與標點、日期統一 `YYYY-MM-DD`，每次以不同種子打亂順序
- **重複執行**：每個條件 5 次，看穩定度
- **指標**：AUC（隨機抽一家問題公司，分數高於隨機一家對照公司的機率；平手算一半）、bootstrap 95% CI、組內勝／平／負、Spearman ρ

### 資料
| 樣本 | 內容 | 模型能否記得結果 | 用於 |
|---|---|---|---|
| 第八輪 | 14 對：AAER（SEC 會計執法）問題公司＋同產業同規模對照，28 家 | 能：多數 AAER 在模型訓練截止（2026-06）前公開 | A、C、D |
| 時間外 | 第九輪 27 對：2026-07-01～10-31 申報 8-K Item 4.02（財報不可再依賴）的公司＋程式選出的同產業同規模對照，54 家 | 不能：事件在訓練截止之後 | B、C、D |

### 提示詞
「只用你已知的知識」，對每家公司給 0–100 的重大誤述風險分數，並回答是否知道該年度後來有會計問題、重編或 SEC 執法（`knows_later_problems`），附一句理由（`basis`），以 JSON 回覆。
內容沿用第八輪原始 MEM 提示，只把「寫入檔案」改成「直接回覆 JSON」（因為沒有寫檔工具）。

### 實驗 A：隔離環境重跑第八輪 MEM
- 第八輪 28 家，Opus 5.5，雲端 5 次（種子 20261107–20261111）
- 使用者在自己的 Mac 上用 terminal 親自執行 1 次（與雲端第 1 次同一份名單），可即時看到執行過程
- 比較對象：原始第八輪 MEM、兩次 claude.ai 重跑（皆 0.88）

### 實驗 B：時間外樣本
- 完全仿照 A，只換資料：時間外 54 家；提示只把公司數 28 改成 54
- 預先登錄的檢驗：5 次全部通過檢查；問題組「知道」≤ 2/27；AUC 與 95% CI；與 A（0.88）、第九輪原始 MEM（0.71）比較
- 判讀標準：若「知道」≈ 0 而 AUC 明顯 > 0.5 → 名稱帶有公司類型先驗

### 實驗 C：不同模型＋「知道／不知道」分層
- 模型：Opus 5.5（沿用 A、B）、Sonnet 5.5、Haiku 5.5（新跑）；effort 用 CLI 預設值
- 第 k 次三個模型看到完全相同的提示與名單（沿用 Opus 第 k 次），唯一差別是模型
- 兩份樣本 × 5 次，新跑 20 次；回答不完整就用同一份名單重跑一次
- 主要指標：每個模型在兩份樣本的 AUC、記憶增量 Δ（第八輪 AUC − 時間外 AUC）
- 分層指標：只用「知道」旗標的 AUC、扣掉「知道」後的殘差 AUC、問題／對照 × 知道／不知道 四格中位數
- 判讀標準：AUC 跟著記憶量變化、時間外各模型相近 → 支持「記得結果」；各模型第八輪 AUC 相近 → 支持「先驗」

### 實驗 D：查核「知道」自述
- 對象：三個模型所有「知道」自述，共 254 則
- 紀錄（只計 2026-07-01 前公開的）：第八輪問題公司用 14 份 AAER 原文；其他公司用 EDGAR 的 8-K 4.02（讀原文）、10-K/A、延遲申報通知，以及 AAER 清單是否出現該公司
- 事實表：協調者依原文撰寫，每項細節對照原文核對，並判定「被問的年度是否有公開問題紀錄」
- 評分者：每家公司一個無工具 Opus session，看事實表＋原文＋該公司全部自述（不標示模型、打亂順序），填四個欄位：問題類型（相符／部分／不符／沒說）、後果（正確／錯誤／沒說）、是否矛盾、該年度是否有紀錄
- 總判定由程式計算：正確且具體／正確但籠統／錯誤／無紀錄支持
- 人工抽查：固定種子抽 51 則（20%），在評分者執行前由協調者判定並 commit
- 判定細則（在抽查與評分前補進預先登錄）：只說「重大缺失」算沒說問題類型；只有事實表涵蓋的事實（問題類型、期間、是否重編、是否 SEC 執法）才算矛盾；期間涵蓋被問年度即不算期間錯誤
- 判讀標準：每個模型的正確比例（M1）≥ 80% → 「知道」是真實記憶；< 60% → 自述不可靠

## 三、實驗環境

### 執行方式
每次評分都是一個全新的 Claude Code session，在新建的空目錄中執行：
```
claude -p "<提示詞＋名單>" --model <模型> --tools "" --strict-mcp-config \
       --setting-sources "" --no-session-persistence --output-format stream-json --verbose
```
| 參數 | 作用 | 擋掉什麼 |
|---|---|---|
| `--tools ""` | 移除所有內建工具 | WebSearch、WebFetch、Bash（curl 等）、讀寫檔、子代理、Skill、ToolSearch |
| `--strict-mcp-config` | 不載入任何 MCP 伺服器 | GitHub、Google Drive、瀏覽器等外部服務 |
| `--setting-sources ""` | 不讀任何設定檔 | CLAUDE.md、記憶、hooks、權限設定 |
| `--no-session-persistence` | 不保存 session | 這次內容不會被下一次讀到 |
| 新建的空目錄 | 沒有任何檔案 | repo 裡的標籤與結果 |
| `--output-format stream-json --verbose` | 每個事件一行 JSON，完整存檔 | （提供證據） |

**為什麼這樣就無法上網**：模型本身只產生文字，上網必須呼叫工具；工具清單是空的，就沒有任何上網管道。

### 為什麼選 CLI，不用 claude.ai App、不靠 sandbox
| 選項 | 問題 |
|---|---|
| claude.ai App | 網路開關要手動操作，事後無法證明；記憶與「搜尋過去對話」可能帶入先前的第八輪結果；沒有可驗證的紀錄 |
| 網路 sandbox | 網路搜尋在 Anthropic 伺服器端執行，模型又必須連到 Anthropic API，只擋網路擋不住搜尋 |
| **CLI（採用）** | 啟動時列出實際可用工具，完整紀錄每個事件與伺服器端計數，可自動化、可重複 |

### 每次執行的 7 項自動檢查（缺少證據即判失敗）
| 檢查 | 依據 |
|---|---|
| 工具清單為空 | 啟動事件 `tools: []` |
| MCP 伺服器為空 | 啟動事件 `mcp_servers: []` |
| 沒有工具呼叫 | 所有輸出區塊只有 `thinking`、`text` |
| 伺服器端搜尋／抓取次數為 0 | `usage.server_tool_use` 與 `modelUsage` 中**每一個模型**的 `webSearchRequests`（API 伺服器計費計數，不是模型自述） |
| 沒有子代理 | `subagent_stats.spawned == 0` |
| 只有一輪 | `num_turns == 1` |
| 正常完成 | `subtype == "success"` |

另外檢查實際服務的模型等於指定的模型（實驗 C）。

### 環境本身的驗證（canary 與正控制）
每個實驗、每個模型正式執行前都先跑兩個 canary：
| canary | 設定 | 預期 | 實際 |
|---|---|---|---|
| 無工具 | 本環境；問 2026-11-05（或 11-06）台股收盤，在訓練截止之後 | 答不出、7 項全過 | 每次都答「不知道」或沒有給出點數，7 項全過 |
| 開放搜尋（正控制） | 只開放 WebSearch | 搜到答案、檢查判定失敗 | 每次都搜到點數（如 41,574.72），檢查判定失敗 |

執行中發現的三件事：
1. **只看主模型的搜尋計數會漏掉**：Claude Code 的搜尋交給另一個模型（`claude-haiku-5-5`）在伺服器端執行，計數只記在那個模型名下，主模型的 `usage` 仍是 0。所以檢查每一個模型的計數
2. **模型會想上網**：Sonnet 5.5 在無工具的 canary 中，在回答文字裡寫出 `curl` 證交所網站的工具呼叫；沒有工具，什麼都沒執行。只靠「請不要上網」的提示不夠，必須移除工具
3. **檢查會在失敗時擋下**：使用者第一次在 Mac 上執行時登入已過期，請求沒送到模型；檢查判定「伺服器計數」與「正常完成」失敗，沒有誤判為通過。重新登入後通過

### 執行地點與版本
| 地點 | Claude Code 版本 | 用於 |
|---|---|---|
| 雲端 session（本 repo 的工作環境） | 2.1.318、2.1.319 | A 的 5 次、B、C、D 的全部 LLM session |
| 使用者自己的 MacBook（terminal） | 2.1.316 | A 的 1 次（含兩個 canary），透過 `watch` 即時顯示 |

### 其他
- 實驗 D 從 SEC 網站下載 AAER 與申報檔時，依 SEC 規定在 User-Agent 附上使用者同意的聯絡 email，只用於 sec.gov 請求，不寫進 repo
- 實驗 D 的評分提示超過 10 萬位元組時，改由標準輸入傳給 `claude -p`（命令列參數上限 128KB），環境與檢查不變
- 費用：每次 MEM 執行約 0.09 美元（Opus）；全部實驗的 LLM 費用約數美元

## 四、實驗結果

### 實驗 A：隔離環境重跑（`results/mem_isolated/`）
| 條件 | AUC | 95% CI | 組內勝／平／負 | 問題公司說「知道」 | 對照公司說「知道」 |
|---|---|---|---|---|---|
| 雲端 run 1–5 | 0.86／0.89／0.88／0.88／0.88 | | 11–12／0–1／2 | 12–13／14 | 1–2／14 |
| **雲端 5 次平均分數** | **0.88** | 0.69–1.00 | 12／0／2 | | |
| 使用者 Mac run1 | 0.86 | 0.67–1.00 | 11／0／3 | 12／14 | 2／14 |
| 原始第八輪；claude.ai 重跑 1、2 | 0.88；0.88、0.88 | | | | |

- 6 次全部通過 7 項檢查
- 與原始 MEM 的 Spearman ρ 0.96–0.98；雲端 5 次之間最低 0.95；Mac 與雲端 run1 為 0.98
- 每次都輸同兩對：Evoqua < Welbilt、Gentex < Visteon（Mac 多輸一對邊界對 Ideanomics < TheMaven）
- **結論**：0.88 在確定無法上網的環境中可重現，不是上網得來的

### 實驗 B：時間外樣本（`results/mem_isolated_oot/`）
| 條件 | AUC | 95% CI | 組內勝／平／負 | 問題公司說「知道」 |
|---|---|---|---|---|
| 隔離 run 1–5 | 0.72／0.67／0.68／0.72／0.68 | | 19–21／1–3／5–6 | 每次 0／27 |
| **5 次平均分數** | **0.69** | 0.54–0.83 | 21／0／6 | |
| 第九輪原始 MEM | 0.71 | 0.57–0.84 | 21／2／4 | 0／27 |

- 5 次全部通過檢查；與第九輪原始 MEM 的 ρ 0.96；5 次之間最低 0.91
- OTC 小型、轉型中的殼公司 40–55 分；IMAX、Liberty Global、NACCO 等大型公司 5–10 分；沒有公司超過 60 分
- **結論**：模型完全不知道結果時，名稱本身仍帶有約 0.69 的公司類型先驗

### 實驗 C：不同模型＋分層（`results/mem_models/`）
**AUC（5 次平均分數）**
| 模型 | 第八輪 | 時間外 | Δ | 第八輪問題公司說「知道」 | 第八輪對照公司說「知道」 |
|---|---|---|---|---|---|
| Opus 5.5 | **0.88**（0.69–1.00） | 0.69 | +0.18 | 90% | 1–2／14 |
| Sonnet 5.5 | **0.84**（0.63–0.99） | 0.69 | +0.15 | 93% | 3–6／14 |
| Haiku 5.5 | **0.79**（0.59–0.95） | 0.70 | +0.09 | 67% | 2／14 |

**分層（第八輪樣本）**
| 模型 | 只用「知道」的 AUC | 扣掉「知道」後的殘差 AUC | 問題公司 知道／不知道 中位數 | 對照公司 知道／不知道 中位數 |
|---|---|---|---|---|
| Opus 5.5 | 0.89 | **0.54** | 85／5 | 80／8 |
| Sonnet 5.5 | 0.81 | 0.63 | 80／5 | 40／10 |
| Haiku 5.5 | 0.76 | **0.54** | 75／10 | 78／8 |

- 20 次新執行全部通過檢查、實際服務的模型正確、一次完整
- 時間外樣本三個模型幾乎相同（0.69–0.70）；時間外的殘差 AUC 0.69–0.70 即為先驗
- 記得最少的 Haiku，第八輪 AUC 與 Δ 都最低
- 預先登錄的順序指標**只部分符合**：Opus 與 Sonnet 說「知道」的比例相近，但 Sonnet AUC 較低（事後觀察：Sonnet 對對照公司也常說「知道」）
- Sonnet 在時間外樣本上有一次說知道 3／27 家問題公司，超過預先登錄的 2／27，已標示
- **結論**：第八輪同一批公司內，分數幾乎完全跟著「說知道」走，扣掉後接近隨機；第八輪這批公司的名稱先驗（0.54–0.63）低於時間外的 0.69

### 實驗 D：查核「知道」自述（`results/mem_factcheck/`）
**第八輪問題公司的「知道」自述**
| 模型 | 則數 | 正確且具體 | 正確但籠統 | **正確合計（M1）** | 錯誤 |
|---|---|---|---|---|---|
| Opus 5.5 | 63 | 86% | 11% | **97%** | 3% |
| Sonnet 5.5 | 65 | 69% | 17% | **86%** | 14% |
| Haiku 5.5 | 47 | 40% | 43% | **83%** | 17% |

**對照公司與時間外樣本的「知道」自述：沒有公開紀錄支持的比例**
| 模型 | 第八輪對照 | 時間外問題 | 時間外對照 |
|---|---|---|---|
| Opus 5.5 | 5／9（全是 Welbilt） | 0 則 | 0 則 |
| Sonnet 5.5 | 17／22 | 10／11 | 22／22 |
| Haiku 5.5 | 5／10 | 0／2（High Wire 確有紀錄） | 3／3 |

**評分可靠度**：人工抽查 51 則，總判定一致 48／51（94%）；欄位一致率：問題類型 84%、後果 92%、矛盾 92%。32 個評分 session 全部通過 7 項檢查、一次完整。

**具體發現**
- 錯誤多是細節記錯，不是憑空捏造：GTT 把「營業成本」記成「營收」、或把不可依賴期間記成 2016–2018（實際 2017–2019）；Evoqua 說 FY2018 被重編（實際沒有重編，只有 SEC 處分）
- Haiku 多半只記得「出過事、重編過」，說不出問題類型（具體只有 40%）
- **Welbilt**（對照）：三個模型 15 則全說「知道」，內容（所得稅重編）是真的，但那是 2016 年的事，被套到被問的 2018 年 → 給 80–85 分，這是 MEM 每次輸掉 Evoqua／Welbilt 這一對的原因
- **Gentex**：模型不記得它出事，每次只給 4–5 分，是另一對每次都輸的原因
- **TheMaven**（對照）：2018 年確有季報不可依賴，但 14 則中 8 則說有 SEC 執法，AAER 清單沒有
- **結論**：三個模型的 M1 都 ≥ 80%，「知道」是真實記憶；Sonnet 會對沒有紀錄的公司說「知道出事」，解釋了它 AUC 較低

### 總結論
1. MEM 的 0.88 在確定無法上網的環境中重現（雲端與使用者電腦、6 次），不是上網得來的
2. 模型不知道結果時，名稱先驗約 0.69（實驗 B）
3. 在第八輪同一批公司內，分數幾乎完全跟著「說知道」走，扣掉後只剩 0.54；記得越少的模型 AUC 越低（實驗 C）
4. 「說知道」與 SEC 紀錄相符（Opus 97%），是真的記憶（實驗 D）

→ **第八輪 MEM 的 0.88 主要來自模型記得這些公司後來出事。** 第七輪「整份 10-K 0.90」在這類模型記得結果的樣本上主要反映記憶，不能解讀為讀年報辨識舞弊的能力；LLM 方法應在時間外樣本或確認模型不知道結果的條件下評估。

- 第八輪只有 14 對，AUC 的 CI 很寬（約 0.6–1.0）；三個模型只看方向，不做顯著性檢定
