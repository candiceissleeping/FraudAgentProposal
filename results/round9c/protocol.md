# 第九輪 c：匿名化階梯——讓「給名單」也認不出公司（預先登錄）

本文件在建立任何 9c 卡片、執行任何 9c agent 之前提交。

## 0. 目的
第九輪 b 顯示：給 54 家名單時，第九輪的 J0 事實卡有 34/54 可被配對回公司（隨機期望 7）。目標一的「不知道是哪家公司」在對抗情境下尚未達成。
本輪把事實卡逐級粗化，找出**在對抗式封閉辨識下也認不出公司**、而且**仍保有區分力**的最細格式。

## 1. 三級卡片（同一份第九輪已驗證事實與 XBRL 特徵，程式產生）
| 等級 | 內容 | 拿掉什麼 |
|---|---|---|
| L1 | 第八輪 8b 的粗化卡（`round8.card_c_text`）：28 個欄位（不含 F23）、比率改成類別、最大客戶比例分四級 | 產業、精確比率、F23 |
| L2 | **類別計數卡**：7 個面向，只給「出現幾個紅旗 / 共幾項」，不說是哪一項 | 個別事實的身分 |
| L3 | **總數卡**：揭露紅旗總數（0–26）＋數字訊號總數（0–4，附可計算項數） | 面向資訊 |

L2 的 7 個面向（`not_found` 視為未出現）：
1. 內控與查核（0–4）：F01 = yes、F03 = adverse、F05 = yes、F06 = yes
2. 前期更正與會計變動（0–3）：F07 ≠ none、F25 = yes、F28 = yes
3. 調查與訴訟（0–3）：F16、F17、F18 = yes
4. 財務壓力（0–4）：F04、F19、F20、F21 = yes
5. 管理層異動（0–2）：F14、F15 = yes
6. 交易複雜度（0–8）：F08、F09、F10、F11、F22、F23、F27 = yes；F12 或 F13 ≥ 25%
7. 數字訊號（0–4，附可計算項數）：M > −1.78；F-score > 1.0；TATA > 0.03；營業現金流 / 淨利 < 0.8

## 2. 檢驗
### 2.1 封閉式辨識（每級一個 agent，54 家名單 + 54 張該級卡，提示同 `data/round9b/probe_closed_prompt.md`）
- **通過標準：配對正確 ≤ 3/54**（均勻隨機期望 1.0）
- 選出**通過的最細等級**（L1 > L2 > L3）作為「K 卡」

### 2.2 K 卡評分
- 54 個新 agent 用同一份 `data/round8/judge_prompt.md` 評 K 卡（J0-K）
- **HK1**：J0-K 的 AUC 95% CI 下界 > 0.5
- 描述性：J0-K 與 J0（0.77）、MEM（0.71）的比較；J0-K 自述知道後來有問題（標準 ≤ 1）；L2／L3 的程式計數直接當分數的 AUC

### 2.3 判讀
- K 卡封閉辨識通過 + HK1 通過 → 在「給候選名單」的對抗情境下，評分輸入也認不出公司，且分數仍有區分力。結合第九輪的時間外設計，目標一的兩層（不知道公司、不知道結果）同時成立
- 三級都未通過 → 如實報告：任何保有內容的卡片都帶有可辨識的指紋
- K 卡通過但 HK1 未通過 → 如實報告：匿名化與區分力之間存在取捨
