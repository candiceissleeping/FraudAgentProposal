# 第五輪實驗流程（預先登錄）：財務數字特徵＋財報一致性檢查

本檔在**下載任何財務數字之前**提交。之後若有修改，一律另開 commit 並寫明原因，不覆寫本檔。

## 1. 目的與假設
第四輪顯示只靠 10-K 文字，鑑別力很弱（關鍵字 AUC 0.56）。第五輪加入兩類以數字為基礎的方法：

- **財務特徵**：用已發表的模型（Beneish M-score、Dechow F-score）衡量盈餘操縱的跡象
- **財報一致性檢查（新增）**：檢查財務報表「自己對不上」的地方，包括報表內恆等式、報表之間的銜接、與去年 10-K 的差異、文字與數字的差異

預先登錄的假設：

| 編號 | 假設 | 檢定方式 |
|---|---|---|
| H1 | 財務特徵有鑑別力 | F-score AUC 的 95% CI 下限 > 0.5 |
| H2 | 一致性檢查有鑑別力 | 一致性分數 AUC 的 95% CI 下限 > 0.5 |
| H3 | 數字＋文字比只用文字好 | (T+F+C) − T 的 AUC 差異，配對 bootstrap 95% CI 下限 > 0 |

T = 第四輪關鍵字分數，F = F-score，C = 一致性分數。

## 2. 樣本
- 沿用第四輪 36 組配對（72 家公司、相同 10-K 會計年度 Y0），這樣可以和文字方法直接比較
- 每家公司下載兩份 10-K：
  - **Y0**：與第四輪相同的年度
  - **Y-1**：前一年度，用於跨年度一致性檢查
- 金融業 3 組（AIG、Fannie Mae、Doral 與各自的對照公司）不適用 M-score 和 F-score，但可以做一致性檢查

## 3. 資料來源
- **SEC EDGAR 原始 10-K**（`www.sec.gov/Archives`）：EDGAR-CORPUS 已移除表格，只能從這裡取得財務數字
  - 2001 年以前多為純文字固定寬度表格，之後多為 HTML 表格
- **SEC submissions API**（`data.sec.gov`）：查詢每家公司各年度 10-K 的檔案編號（accession number）
- 下載時的 User-Agent 依 SEC 規定填寫聯絡資訊；請求頻率每秒不超過 5 次

## 4. 擷取科目
從 Y0 10-K 擷取 Y0 和 Y-1 兩年的數字。損益表和現金流量表若有第三年也一併擷取。從 Y-1 10-K 擷取它當年申報的 Y-1 數字。

| 報表 | 科目 |
|---|---|
| 損益表 | 營收、銷貨成本、毛利、銷管費用、折舊攤銷、營業利益、稅前利益、淨利、稀釋 EPS、稀釋加權股數 |
| 資產負債表 | 現金、應收帳款淨額、存貨、流動資產合計、固定資產淨額、總資產、流動負債合計、長期負債、負債合計、股東權益合計、保留盈餘 |
| 現金流量表 | 淨利（首行）、折舊、應收帳款變動、存貨變動、營業 / 投資 / 融資現金流、匯率影響、現金淨變動、期初 / 期末現金、發行股票所得、發放股利 |
| 其他 | 季度營收與淨利（若有季度表）、各部門營收合計（若有） |

**擷取程序**
1. 程式把表格轉成「科目名稱＋數字欄」，再用同義詞清單比對科目（例如 net sales / total revenues / revenues）
2. 單位（千元、百萬元）由表頭判斷，統一換算成百萬元
3. 程式擷取失敗的科目，由人工從同一份表格補填，並在 `source` 欄註記 `manual`
4. 每個數字記錄出處（檔案、表格、原始字串），可追溯

## 5. 方法 F：財務特徵（使用已發表的係數，不重新擬合）

### F1：Beneish M-score（1999，8 變數模型）
M = −4.84 + 0.920·DSRI + 0.528·GMI + 0.404·AQI + 0.892·SGI + 0.115·DEPI − 0.172·SGAI + 4.679·TATA − 0.327·LVGI

| 變數 | 定義（t = Y0、t−1 = Y-1） |
|---|---|
| DSRI | (應收_t / 營收_t) ÷ (應收_t−1 / 營收_t−1) |
| GMI | 毛利率_t−1 ÷ 毛利率_t |
| AQI | [1 − (流動資產+固定資產)/總資產]_t ÷ [同]_t−1 |
| SGI | 營收_t ÷ 營收_t−1 |
| DEPI | [折舊/(折舊+固定資產)]_t−1 ÷ [同]_t |
| SGAI | (銷管/營收)_t ÷ (銷管/營收)_t−1 |
| LVGI | [(流動負債+長期負債)/總資產]_t ÷ [同]_t−1 |
| TATA | (持續營業淨利 − 營業現金流)_t ÷ 總資產_t |

- 門檻：M > −1.78 標記為「可能操縱」
- 缺少某一變數時，該變數設為 1（中性值；TATA 設為 0）。缺少超過 3 個時，M-score 記為無法計算

### F2：Dechow 等（2011）F-score，模型 1
預測值 = −7.893 + 0.790·rsst_acc + 2.518·ch_rec + 1.191·ch_inv + 1.979·soft_assets + 0.171·ch_cs − 0.932·ch_roa + 1.029·issue

F-score = 機率 ÷ 無條件機率 0.0037，其中機率 = e^預測值 / (1 + e^預測值)。

| 變數 | 定義 |
|---|---|
| rsst_acc | (ΔWC + ΔNCO + ΔFIN) ÷ 平均總資產；資料不足時改用 (淨利 − 營業現金流) ÷ 平均總資產，並註記 |
| ch_rec | Δ應收 ÷ 平均總資產 |
| ch_inv | Δ存貨 ÷ 平均總資產 |
| soft_assets | (總資產 − 固定資產 − 現金) ÷ 總資產 |
| ch_cs | 現金銷貨變動率，現金銷貨 = 營收 − Δ應收 |
| ch_roa | 淨利_t/平均總資產_t − 淨利_t−1/平均總資產_t−1；需要第三年資產時，若無則以期末資產代替 |
| issue | 當年有發行股票或債券 = 1，否則 = 0 |

- 門檻：F > 1.0 為高於平均風險，F > 2.45 為高風險（原文分級）

### F3：簡單指標（只用於解釋，不檢定）
應計比率、應收成長 − 營收成長、存貨成長 − 營收成長、營業現金流 ÷ 淨利、Altman Z（財務壓力）

## 6. 方法 C：財報一致性檢查（新增）

### 6.1 容忍誤差
差異 ≤ max(較大項目的 0.5%, 報表最小單位的 2 倍) 視為一致。報表最小單位用來處理四捨五入，例如以百萬元表達時為 2 百萬。EPS 的容忍誤差為 $0.02。

### 6.2 檢查清單

**類型 I：報表內恆等式（權重 3）**

| 代號 | 檢查 |
|---|---|
| I-1 | 總資產 = 負債合計 + 少數股權 + 股東權益（Y0、Y-1 各一次） |
| I-2 | 流動資產各項加總 = 流動資產合計 |
| I-3 | 營收 − 銷貨成本 = 毛利（有列毛利時） |
| I-4 | 營業 + 投資 + 融資現金流 + 匯率影響 = 現金淨變動 |
| I-5 | 期初現金 + 現金淨變動 = 期末現金 |
| I-6 | 稀釋 EPS ≈ 淨利 ÷ 稀釋加權股數 |

**類型 II：報表之間的銜接（權重 2）**

| 代號 | 檢查 |
|---|---|
| II-1 | 損益表淨利 = 現金流量表首行淨利 |
| II-2 | 現金流量表期末現金 = 資產負債表現金（考慮受限現金等揭露項目） |
| II-3 | 保留盈餘_t ≈ 保留盈餘_t−1 + 淨利 − 股利（容忍誤差放寬為總資產的 0.5%） |
| II-4 | 現金流量表的應收帳款變動 ≈ 資產負債表應收帳款的變動（容忍誤差為總資產的 1%） |
| II-5 | 現金流量表的存貨變動 ≈ 資產負債表存貨的變動（同上） |
| II-6 | 四季營收、淨利加總 = 全年數字 |
| II-7 | 各部門營收加總（扣除內部沖銷）= 合併營收 |

**類型 III：跨年度一致（權重 3）**

| 代號 | 檢查 |
|---|---|
| III-1 | Y0 10-K 中的 Y-1 數字 vs Y-1 10-K 原本申報的數字，比較營收、淨利、總資產、股東權益、營業現金流、應收帳款 |

- 差異超過容忍誤差，且文中**沒有**標示重編（restated）、重分類（reclassified）、停業部門或會計原則變更 → 記為「未說明的修正」，計入失敗
- 有標示的修正另外記錄為「已說明的修正」，不計入失敗，因為第四輪的文字方法已經抓得到

**類型 IV：文字與數字（權重 1）**

| 代號 | 檢查 |
|---|---|
| IV-1 | MD&A（EDGAR-CORPUS 的 Item 7）中明確寫出的營收、淨利金額或成長率 vs 報表數字 |

- 只比對同一句同時出現「科目＋年度＋金額或百分比」的句子；差異 > 1% 記為失敗

### 6.3 「解釋得通」的處理
程式判定失敗的每一項，都由人工回到原始表格確認：

- **擷取錯誤**（抓錯欄、抓錯單位）→ 修正數字後重新檢查，不計入失敗
- **有揭露的合理原因**（例如受限現金、併購造成的應收變動、停業部門、匯率）→ 記為「解釋得通」，寫下理由，不計入失敗
- **找不到解釋** → 計入失敗

每一項判斷都寫入 `consistency_checks.csv`，欄位為：公司、檢查代號、數值 A、數值 B、差異、結果（通過 / 失敗 / 解釋得通 / 無法檢查）、理由。

### 6.4 一致性分數
C = 100 × Σ(權重 × 失敗) ÷ Σ(權重 × 可檢查)

另外報告失敗件數，以及「已說明的修正」件數。

## 7. 比較的方法

| 代號 | 方法 | 備註 |
|---|---|---|
| T | 第四輪關鍵字分數 | 不受辨識影響，作為基準 |
| M | Beneish M-score | 金融業除外 |
| F | Dechow F-score | 金融業除外 |
| C | 一致性分數 | 全部 72 家 |
| T+F | 排名平均 | 不擬合權重 |
| T+F+C | 排名平均 | 主要的組合方法 |
| R+F+C | 規則 v2 + F + C | 受辨識污染，只作參考 |

排名平均的做法：每個方法在樣本內轉成百分位排名，再取平均。某方法無法計算時，以其餘方法平均。

## 8. 評估
- 每個方法的 AUC 與 bootstrap 95% CI（2000 次）
- 組內勝率：問題公司分數 > 對照公司的組數
- H3：配對 bootstrap 計算 AUC 差異的 CI
- 門檻分類：M > −1.78、F > 1.0、C > 0 的命中率（treatment 中被標記的比例）與誤報率（control 中被標記的比例）
- 敏感度分析：
  - (a) 排除事後揭露的 AIG、ITT、Navistar 三組
  - (b) 排除金融業三組
  - (c) 只用程式自動擷取、未經人工補值的數字

## 9. 盲性與偏誤控制
- 數字擷取無法盲測，因為下載時就知道公司名稱
- 控制方式：
  - 所有判斷依本檔事先寫好的規則與容忍誤差
  - 按 CIK 順序處理，treatment 與 control 交錯
  - 「解釋得通」必須引用原文理由
- M-score 和 F-score 是公式，沒有主觀空間
- 一致性檢查中「解釋得通」的人工判斷是主要偏誤來源。因此另外報告「不做人工判斷、只看程式結果」的版本
- 程序：
  1. 所有特徵值與檢查結果先寫入 `financial_features.csv`、`consistency_checks.csv` 並提交
  2. 提交後才與 treatment / control 標籤合併計算 AUC

## 10. 事先承認的限制
- 33–36 組的樣本下，AUC 的 CI 約為 ±0.13，只能偵測大幅改善
- Beneish 和 Dechow 的模型是用 AAER 公司建立的，用在 AAER 樣本上可能稍微偏樂觀
- 部分公司的舞弊年度與 Y0 不完全重疊，數字訊號可能出現在更早或更晚的年度
- 舊式純文字表格的擷取錯誤率較高；以敏感度分析 (c) 檢驗
